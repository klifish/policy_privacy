# Policy Indistinguishability 实验：三层攻击模型详解

## 📋 执行摘要

Policy Indistinguishability（策略不可区分性）实验旨在验证：**当访问控制策略内容被零知识证明隐藏后，语义相似的策略在链上观察者眼中是否真正不可区分。**

本实验设计了三个递增强度的攻击层级，从简单的机器学习分类到高级统计检验，全面评估系统的隐私保护能力。只有当所有三层攻击都无法有效区分策略时，才能声称系统满足不可区分性要求。

---

## 🎯 实验核心目标

### 研究问题

在医疗数据访问控制场景中，即使策略内容被加密隐藏，链上执行痕迹（如 gas 消耗、calldata 大小、日志信息等）是否会泄露足够信息，使攻击者能够区分不同策略？

### 威胁模型

**攻击者能力**：
- 可以观察所有链上公开信息
- 可以记录多次策略执行的痕迹
- 拥有机器学习和统计分析能力
- **但无法**：破解零知识证明，访问链下数据

**攻击目标**：
- 识别特定策略的身份
- 判断两个观察到的执行是否来自同一策略
- 检测策略间的微小差异

---

## 📊 可观察特征

实验只使用**链上可观察**的 9 个特征：

| 特征类别 | 具体特征 | 含义 |
|---------|---------|------|
| **Gas 消耗** | `commitGasUsed` | commit 交易消耗的 gas |
|  | `accessGasUsed` | access 交易消耗的 gas |
| **数据大小** | `commitCalldataLength` | commit 交易的 calldata 长度 |
|  | `accessCalldataLength` | access 交易的 calldata 长度 |
|  | `proofSize` | 零知识证明的大小 |
| **事件日志** | `commitLogsCount` | commit 交易的日志数量 |
|  | `commitLogsSize` | commit 交易的日志总大小 |
|  | `accessLogsCount` | access 交易的日志数量 |
|  | `accessLogsSize` | access 交易的日志总大小 |
| **时间** | `blockDifference` | 两次交易的区块间隔 |

**关键决策**：排除了客户端侧信息（如证明生成时间），因为这些不属于链上可观察数据。

## 🔬 策略对分类

实验构造四种类型的策略对来测试不同场景：

### 1. Semantic Equivalent（语义等价）
- **定义**：语义完全相同但实现方式不同
- **例子**：同一条规则用不同的电路结构实现
- **预期**：应该完全不可区分

### 2. Structural Variant（结构变体）
- **定义**：相同语义，但执行参数配置不同
- **例子**：相同策略在不同的 gas limit 或优化级别下执行
- **预期**：应该不可区分

### 3. Weak Equivalent（弱等价）
- **定义**：语义高度相似但非完全等价
- **例子**：允许"心脏病研究者"vs"心血管疾病研究者"
- **预期**：应该难以区分

### 4. Controlled Difference（对照差异）
- **定义**：语义有明显差异的策略对
- **例子**：允许"研究用途"vs"商业用途"
- **预期**：可能被区分（作为对照组）

## 📍 Level I: Single-Sample Attacks

### 攻击场景

**威胁模型**：攻击者观察到某个策略的多次执行痕迹。

**攻击任务**：从执行特征中识别"这是哪个策略"。

**类比**：就像通过一个人的多次行为模式识别其身份。

### 方法设计

#### 数据准备
- 收集每个策略的多次执行数据
- 每次执行包含 9 维特征向量
- 标签 = 策略在策略对中的索引（0 或 1）

#### 分类器选择

**1. 逻辑回归（Logistic Regression）**
- 学习特征的线性组合来预测策略
- 输出预测概率：P(策略 = A | 特征)
- 优势：可解释性强，能看到每个特征的权重

**2. 随机森林（Random Forest）**
- 捕捉非线性关系和特征交互
- 多棵决策树的集成
- 优势：能发现复杂模式

### 评估指标

| 指标 | 含义 | 隐私保护的期望值 |
|------|------|-----------------|
| **AUC** | 分类器区分能力 | ≤ 0.55（接近随机 0.5） |
| **Accuracy** | 分类准确率 | ≈ 50% |
| **Advantage** | 超过随机猜测的优势 | ≤ 5% |
| **Entropy** | 预测不确定性 | 接近 1（完全不确定） |
| **Permutation p-value** | AUC 是否显著 | ≥ 0.05（不显著） |

### 特征重要性分析

逻辑回归的权重向量揭示了哪些特征最能区分策略：

```
高权重特征 → 该特征能有效区分策略 → 隐私泄露！
低权重特征 → 该特征无法区分策略 → 隐私保护良好 ✅
```

**示例解读**：
- 如果 `commitGasUsed` 权重 = 0.82 → gas 消耗是强判别信号 ❌
- 如果所有权重都接近 0 → 无特征能有效区分 ✅

### 置换检验（Permutation Test）

**目的**：验证分类器的 AUC 是否真正显著，还是只是随机波动。

**方法**：
1. 记录实际 AUC 值
2. 随机打乱标签 500 次，每次计算 AUC
3. 统计有多少次随机 AUC ≥ 实际 AUC
4. p-value = 超过实际 AUC 的比例

**解读**：
- p ≥ 0.05 → 实际 AUC 不显著，可能只是运气 ✅
- p < 0.05 → 实际 AUC 显著，分类器真的有效 ❌

### Level I 的意义

1. **基线测试**：最简单的攻击方式，是隐私保护的第一道防线
2. **指纹检测**：测试单个策略是否有独特的可识别特征
3. **泄露定位**：通过特征权重识别哪些特征导致泄露
4. **系统诊断**：指导优化方向（如需要对哪些特征添加混淆）

**通过标准**：分类器应接近随机猜测水平（AUC ≈ 0.5）。

## 🎯 Level II: Pairwise Attacks

### 攻击场景

**威胁模型**：攻击者观察到两个策略（A 和 B）的多次执行痕迹。

**攻击任务**：判断这两组执行是来自"同一策略"还是"不同策略"。

**类比**：通过对比两个人的行为模式，判断是否同一人。

### 核心创新：差分特征

**关键思想**：不直接使用原始特征，而是使用特征的**绝对差值**。

#### 为什么使用差分？

```
场景 1: 策略 A vs 策略 B（不同策略）
A: commitGas = 50000, proofSize = 1024
B: commitGas = 52000, proofSize = 1280
差值: |50000 - 52000| = 2000, |1024 - 1280| = 256

场景 2: 策略 A 的两次执行（同一策略）
A₁: commitGas = 50000, proofSize = 1024
A₂: commitGas = 50100, proofSize = 1024
差值: |50000 - 50100| = 100, |1024 - 1024| = 0
```

**分类目标**：学习区分"策略间差异"和"执行间随机噪声"。

如果无法区分 → 策略间差异 ≈ 执行噪声 → **不可区分** ✅

### 正负样本构造

#### 正样本（label = 1，不同策略）
- 策略 A 的执行 vs 策略 B 的执行
- 差分特征应该较大（如果策略不同）

#### 负样本（label = 0，同一策略）
- 策略 A 的执行 1 vs 策略 A 的执行 2
- 策略 B 的执行 1 vs 策略 B 的执行 2
- 差分特征应该较小（执行间随机波动）

**关键设计**：负样本提供了"同一策略应有的差异基线"，使分类器能学习"多大差异算不同策略"。

### 方法特点

这是典型的 **Siamese Network** 思想：

```
传统分类：学习 A 的特征 → 识别 A
Pairwise：学习 |A - B| → 判断是否同一策略
```

**优势**：
- **平移不变性**：对整体偏移不敏感
- **对称性**：A vs B = B vs A
- **直接建模相似性**：更符合不可区分性定义

### Level II 的核心意义

**这是最关键的测试层！**

1. **直接测试不可区分性定义**
   - 密码学定义：攻击者无法判断两个密文是否加密了相同消息
   - Level II 类比：攻击者无法判断两组执行是否来自相同策略

2. **更强的威胁模型**
   - Level I：只观察单个策略
   - Level II：可以比较多个策略
   - 更接近实际攻击场景

3. **实用性验证**
   - 真实场景中的隐私问题往往涉及比较
   - 例如："Alice 和 Bob 的访问策略是否相同？"

**通过标准**：分类器应无法区分策略内差异和策略间差异（AUC ≈ 0.5）。

## 🔍 Level III: Two-Sample Statistical Tests

### 攻击场景

**威胁模型**：攻击者是统计学专家，使用非参数统计方法检测分布差异。

**攻击任务**：判断两个策略的特征分布是否在统计上显著不同。

**类比**：医学研究中比较两组病人的指标分布是否有差异。

### 为什么需要 Level III？

#### Level I & II 的局限性

```
机器学习分类器的限制：
- 需要训练数据（可能不足）
- 依赖模型选择和超参数
- 可能欠拟合，没学到真实差异
- 只能捕捉已学到的模式
```

#### Level III 的优势

```
统计检验 = 无需训练的"分类器"
- 直接比较分布，无需训练
- 有严格的数学和统计理论基础
- 能检测机器学习模型遗漏的微小差异
- p-value 有清晰的概率解释
```

### 方法 1: MMD（Maximum Mean Discrepancy）

#### 核心思想

测量两个分布在**高维特征空间**中的距离。

**直观理解**：
1. 将所有数据点映射到高维空间（通过核函数）
2. 计算策略 A 的样本的"平均位置"
3. 计算策略 B 的样本的"平均位置"
4. MMD = 两个"平均位置"的距离

#### 数学直觉

```
MMD²(A, B) = E[相似度(A内部样本)]
           + E[相似度(B内部样本)]
           - 2×E[相似度(A与B之间)]
```

**几何图景**：

```
情况 1: 分布相同
    ● ○ ● ○ ● ○    (A 和 B 混在一起)
    ○ ● ○ ● ○ ●

    A 内部相似 ≈ B 内部相似 ≈ A-B 之间相似
    MMD ≈ 0 ✅

情况 2: 分布不同
    ● ● ● ● ●      (A 在左边)
            ○ ○ ○ ○ ○  (B 在右边)

    A 内部相似很高，B 内部相似很高
    A-B 之间相似很低
    MMD 很大 ❌
```

#### RBF 核函数

使用高斯核（RBF kernel）测量相似度：

```
K(x, y) = exp(-||x - y||² / 2σ²)
```

- 距离近 → K ≈ 1（非常相似）
- 距离远 → K ≈ 0（不相似）
- σ（带宽）自动选择（中位数启发式）

#### 评估标准

- **MMD ≤ 0.05**：分布距离很小，不可区分 ✅
- **MMD > 0.05**：分布显著不同，可区分 ❌

### 方法 2: KS Test（Kolmogorov-Smirnov Test）

#### 核心思想

比较两个**一维分布**的累积分布函数（CDF）。

**逐特征检验**：对每个特征（如 commitGasUsed, proofSize 等）单独进行 KS 测试。

#### 统计量定义

```
D = max |CDF_A(x) - CDF_B(x)|
    x∈ℝ
```

D = 两个 CDF 之间的最大垂直距离

#### 可视化理解

```
策略 A 的 CDF (commitGasUsed):

1.0 |                    ┌─────
    |                ┌───┘
0.5 |          ┌─────┘         ← 50% 的执行 gas < 50k
    |     ┌────┘
0.0 |─────┘
    └─────────────────────────► gas
    0   20k  40k  60k  80k

策略 B 的 CDF:

1.0 |                    ┌─────
    |               ┌────┘      ← 稍有偏移
0.5 |        ┌──────┘
    |   ┌────┘
0.0 |───┘
    └─────────────────────────► gas

D = max |CDF_A - CDF_B| = 0.15
```

#### 假设检验框架

**零假设 H₀**：两个分布相同
**备择假设 H₁**：两个分布不同

**p-value 解读**：
- p ≥ 0.05 → 不拒绝 H₀，分布可能相同 ✅
- p < 0.05 → 拒绝 H₀，分布显著不同 ❌

#### 诊断能力

KS 测试对每个特征单独检验，可以精确定位问题：

```
结果示例:
- commitGasUsed:  D=0.14, p=0.52 ✅
- proofSize:      D=0.92, p=0.003 ❌ (问题特征！)
- commitLogsSize: D=0.10, p=0.64 ✅
```

**结论**：`proofSize` 的分布显著不同，需要标准化处理。

### Level III 的评估指标

| 检验方法 | 指标 | 隐私保护的期望值 |
|---------|------|-----------------|
| **MMD** | 分布距离 | ≤ 0.05 |
| **KS Test** | p-value（每个特征） | 所有 p ≥ 0.05 |

### Level III 的独特价值

1. **最严格的隐私测试**
   - 敏感度最高，能检测微小差异
   - 即使 Level I & II 通过，Level III 仍可能发现问题

2. **理论基础扎实**
   - 基于假设检验的数学框架
   - p-value 有清晰的概率解释
   - 不依赖模型选择和训练

3. **精确的诊断能力**
   - MMD：整体分布是否不同
   - KS：哪个特征导致差异
   - 可以精确指导系统优化

4. **与密码学不可区分性对应**
   - 密码学定义：任意 PPT 算法无法区分
   - Level III：最敏感的统计方法无法区分
   - 提供理论声明的实证支持

**通过标准**：MMD 小且所有特征的 KS p-value 都不显著。

## 🔗 三层攻击的互补性

### 递进关系

```
┌────────────────────────────────────────┐
│ Level I: 基线防御                       │
│ 测试: 策略有无独特指纹                  │
│ 如果失败 → 连最基本的隐私都没有          │
├────────────────────────────────────────┤
│ Level II: 核心测试                      │
│ 测试: 不可区分性的形式化定义             │
│ 如果失败 → 不满足不可区分性要求          │
├────────────────────────────────────────┤
│ Level III: 最严格验证                   │
│ 测试: 统计上的微小差异                  │
│ 如果失败 → 存在统计泄露                 │
└────────────────────────────────────────┘

只有全部通过 → ✅ 强隐私保证
```

### 互补场景

#### 场景 1: Level II 通过但 Level III 失败

```
Level II: AUC = 0.52 ✅ (分类器随机)
Level III: MMD = 0.068 ❌ (分布有差异)
```

**解释**：
- 分类器表达能力有限，没学到真实差异
- 但统计检验捕捉到了微小的分布偏移
- **Level III 救场！** 发现了遗漏的泄露

#### 场景 2: Level II 失败但 Level III 通过

```
Level II: Accuracy = 0.68 ❌ (分类器有效)
Level III: MMD = 0.018 ✅ (分布无差异)
```

**解释**：
- 可能数据集太小，分类器过拟合
- 或存在特征组合模式，但单个特征分布正常
- **需要进一步调查训练集大小和质量**

### 多角度验证

| 维度 | Level I | Level II | Level III |
|------|---------|----------|-----------|
| **方法** | 监督学习 | Siamese 学习 | 统计检验 |
| **输入** | 原始特征 | 差分特征 | 特征分布 |
| **威胁** | 弱攻击者 | 中等攻击者 | 强攻击者 |
| **捕捉** | 身份特征 | 相对差异 | 分布差异 |
| **优势** | 可解释性 | 不可区分性 | 最严格 |

## 📈 实验阈值设计

### 隐私保护的判定标准

| 层级 | 指标 | 阈值 | 含义 |
|------|------|------|------|
| **Level I** | AUC | ≤ 0.55 | 接近随机猜测（0.5） |
|  | Advantage | ≤ 0.05 | 优势不超过 5% |
|  | Permutation p | ≥ 0.05 | AUC 不显著 |
| **Level II** | AUC | ≤ 0.55 | 无法判断同异 |
|  | Advantage | ≤ 0.05 | 判断优势 ≤ 5% |
|  | Permutation p | ≥ 0.05 | AUC 不显著 |
| **Level III** | MMD | ≤ 0.05 | 分布距离很小 |
|  | KS p-value | ≥ 0.05 | 所有特征不显著 |

### 阈值的合理性

#### AUC = 0.55 的选择

```
AUC = 0.5  → 完全随机
AUC = 0.55 → 允许 5% 的轻微偏差（容忍随机波动）
AUC = 0.6  → 开始有轻微泄露
AUC = 0.7+ → 显著泄露
```

#### Advantage = 0.05 的选择

```
随机猜测: 50% 准确率
允许: 55% 准确率（5% 优势）
拒绝: 60%+ 准确率（10%+ 优势）
```

这是常见的隐私保护阈值，在多个研究中被采用。

#### MMD & p-value = 0.05 的选择

```
α = 0.05 是统计学标准显著性水平
含义: 5% 的假阳性率（错误拒绝零假设的概率）
```

## 🎓 实验的科学意义

### 1. 量化隐私保证

本实验声明: "即使观察 N 次执行，攻击者区分成功率 ≤ 55%"

### 2. 对抗性评估

**模拟多种攻击方法，测试最坏情况下的隐私性**

- 机器学习攻击（Level I & II）
- 统计分析攻击（Level III）
- 覆盖从简单到复杂的攻击谱

### 3. 侧信道分析

**验证即使内容被隐藏，执行痕迹是否泄露信息**

```
问题: 零知识证明隐藏了策略内容，是否足够？

```

**精确定位泄露源，指导系统改进**

## 🎯 总结

### 核心贡献

本实验设计了一个**三层递进**的攻击框架来验证策略不可区分性：

1. **Level I (Single-Sample)**：测试策略是否有独特指纹
2. **Level II (Pairwise)**：直接测试不可区分性定义
3. **Level III (Statistical)**：最严格的分布差异检验

### 独特优势

- ✅ **全面性**：覆盖从弱到强的攻击者
- ✅ **互补性**：机器学习 + 统计检验
- ✅ **可操作性**：明确的阈值和判定标准
- ✅ **诊断性**：精确定位泄露源
- ✅ **严格性**：只有全部通过才声称安全

### 理论意义

- 为密码学不可区分性提供实证支持
- 验证侧信道信息不泄露策略内容
- 量化隐私保证的程度

### 实践价值

- 指导系统优化（如 gas padding, proof 标准化）
- 为安全声明提供可信证据
- 可用于持续监控和回归测试

**最终目标**：证明在医疗数据访问控制场景中，即使所有链上信息都被观察，语义相似的策略仍然**计算上不可区分**，从而保护策略制定者的隐私意图。
