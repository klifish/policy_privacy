# 数据集生成策略对比

## 概述

我们提供了两种策略来确保生成的数据集满足三个实验的需求：

1. **验证优先策略**（Validation-First）- 推荐
2. **约束感知策略**（Constraint-Aware）- 实验性

## 方法1: 验证优先策略 ✅ 推荐

### 工作流程

```
生成数据集 → 验证需求 → 如果失败 → 调整配置 → 重新生成
    ↓           ↓
   快速       无成本
  (2-5秒)    (无区块链)
```

### 使用方法

```bash
# 1. 运行验证
node unified_dataset_validator.js

# 2. 如果失败，调整配置后重试
cp unified_dataset_config.example.json my_config.json
vim my_config.json  # 调整policyCount等参数
node unified_dataset_validator.js --config=my_config.json

# 3. 验证通过后执行链上操作
```

### 优点

✅ **简单直接**：使用现有的PCH生成器，无需修改
✅ **快速迭代**：验证只需几秒钟，可以快速调整
✅ **灵活性高**：可以随时调整验证阈值
✅ **风险低**：不会生成过于复杂或不支持的策略
✅ **已测试**：经过验证，稳定可靠

### 缺点

⚠️ **可能需要多次迭代**：第一次可能不满足所有需求
⚠️ **手动调整**：需要人工分析验证结果并调整配置

### 适用场景

- 你希望快速开始，容许几次迭代
- 你对生成器的内部逻辑不太熟悉
- 你希望使用稳定、经过测试的代码
- **推荐用于生产环境**

## 方法2: 约束感知策略 🧪 实验性

### 工作流程

```
分析约束 → 计算目标 → 生成定制化语义层 → 一次生成满足需求
    ↓           ↓              ↓
  自动化     数学计算       定向生成
```

### 使用方法

```bash
# 直接生成，自动满足约束
node constraint_aware_generator.js

# 或使用自定义配置
node -e "
  const { generateConstraintAwareDataset } = require('./constraint_aware_generator');
  generateConstraintAwareDataset({
    policyCount: 200,
    executionsPerPolicy: 5,
    validation: { /* 自定义阈值 */ }
  }).then(r => console.log('Done!'));
"
```

### 工作原理

1. **分析约束**：计算每个维度需要多少策略
   ```javascript
   PCH: 每个DUO需要 200/6 ≈ 33个策略
   SPP: 每个类别需要 200/4 ≈ 50个策略
   ```

2. **生成平衡的语义层**：
   ```javascript
   Layer 1: GR策略 (33个)
   Layer 2: DS策略 (33个)
   ...
   ```

3. **调整生成参数**：
   - 增加否定概率以生成`negation_heavy`
   - 增加嵌套概率以生成`deep`结构
   - 多样化白名单大小以覆盖所有`SET_SIZE`类别

### 优点

✅ **理论上一次成功**：根据需求定向生成
✅ **自动化**：无需人工迭代
✅ **精确控制**：可以精确指定每个类别的数量

### 缺点

❌ **复杂度高**：需要理解生成器的内部逻辑
❌ **脆弱性**：可能生成不支持的组合（如POA、GS、CC的限制）
❌ **难以完美**：某些SPP维度（如逻辑结构、嵌套深度）难以精确控制
❌ **未充分测试**：目前仍是实验性实现
⚠️ **可能失败**：生成过于复杂的策略可能超过电路深度限制

### 适用场景

- 你需要生成非常大的数据集（>500个策略）
- 你对生成器内部逻辑非常熟悉
- 你希望探索更高级的生成策略
- **仅推荐用于研究和实验**

## 实际案例

### 案例1: 标准场景（200策略）

**需求**：200个策略，5次执行/策略

**推荐**：验证优先

**原因**：
- 数据集大小适中
- 标准配置，风险低
- 即使需要2-3次迭代也很快

**流程**：
```bash
# 第1次
node unified_dataset_validator.js
# 结果: PCH通过, SPP失败(negation_heavy不足), PI通过

# 调整: 增加policyCount到220
vim my_config.json  # policyCount: 220

# 第2次
node unified_dataset_validator.js --config=my_config.json
# 结果: 全部通过 ✅
```

### 案例2: 大规模数据集（500+策略）

**需求**：500个策略用于更高统计功效

**推荐**：可以尝试约束感知，但备用验证优先

**原因**：
- 数据集大，迭代成本较高
- 可以尝试自动化方法
- 但保留Plan B

**流程**：
```bash
# 尝试约束感知
node constraint_aware_generator.js --policyCount=500

# 如果成功 → 太好了！
# 如果失败 → 回退到验证优先
node unified_dataset_validator.js --config=large_config.json
```

### 案例3: 研究新的验证需求

**需求**：测试新的SPP维度或PI指标

**推荐**：验证优先

**原因**：
- 需求还在探索阶段
- 需要灵活调整阈值
- 约束感知不够灵活

## 结论

**对于绝大多数场景，我们推荐使用【验证优先策略】**：
- ✅ 简单、稳定、可靠
- ✅ 快速迭代（几秒钟）
- ✅ 灵活性高
- ✅ 经过充分测试

**【约束感知策略】目前是实验性的**：
- 🧪 仍在开发和测试中
- 🧪 适合研究和探索
- 🧪 对大规模数据集可能有帮助
- ⚠️  不建议用于生产环境
